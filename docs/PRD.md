> **目标首发市场**：中国大陆，简体中文
> **对应项目**：`mereithhh/realtime-salary` 及其本地 Web、SwiftUI 客户端
> **适用读者**：产品、交互、视觉、内容、Web、iOS、测试、安全、法务与运营
> **状态**：待用户访谈、薪酬规则复核、真机技术验证后进入开发冻结

**结论先行：**“下班回血器”不应继续被定义为一个把月薪除到每秒的趣味工具，而应成为面向中国打工人的**私人劳动价值账本 + 下班情绪收口仪式**：先把工资、班次、加班、奖金、提成和扣款按可解释口径记清，再通过 30–60 秒的封账仪式帮助用户把工作留在今天。市场上的实时工资产品已把小组件、倒计时、历史报表和简单隐私模式做成基础门槛，但复杂奖金确定性、可追溯结算、负责任的情绪闭环仍是空白。产品的核心信任不是“数字每秒都跳”，而是每个数字都能回答“怎么算、基于什么、确定到什么程度”，且**工资和情绪默认不离开设备**。首版以固定月薪和时薪人群完成“开工—记录—结算—收工”闭环，不承诺法定工资、个税或心理疗效；复杂提成、轮班、工资条核对分阶段扩展。成功标准不是用户工作更久，而是用户更稳定地结算、更少漏记、对金额更有把握，并在封账后感到“轻松一点或更有掌控感”。

## 1. 背景、机会与证据摘要

### 1.1 当前产品基线与问题

当前开源项目已经具备实时收入、下班倒计时、暂停/继续、小确幸换算、本地保存和基础 SwiftUI 客户端，是一个合格的体验原型；但其数据模型仍主要是“金额 + 年/月/周/小时周期 + 每日工时 + 节假日天数 + 奖金比例”。Web 将完整档案写入 `localStorage`，iOS 将完整档案和记录写入 `UserDefaults`，都不满足工资敏感数据的正式产品安全要求。现有算法用平均工作秒数平摊收入，无法回答真实班次、跨午夜、计薪休息、工作日/休息日/法定节假日加班、奖金系数、阶梯提成、退款冲回和“已赚但未到账”等问题。

品类的最低门槛已经升高。DoneAt、牛马计时器等直接竞品已经覆盖复杂排班、跨午夜、休息、加班、小组件、Live Activity、历史和可选同步；HoursTracker 等成熟工具进一步覆盖工资周期、加减项、报表、Face ID 与工资核对。用户公开反馈反复指向五种失信点：组件不实时、复杂班次不准、跨日累计错误、收入模型僵硬、轻工具订阅价值不匹配。奖金则仍普遍停留在“填一个年奖金”或“手动加一笔收入”，缺少目标奖金率、个人/公司系数、提成规则、情景预测和确定性状态。相关竞品证据见[打工喵](https://apps.apple.com/cn/app/%E6%89%93%E5%B7%A5%E5%96%B5-%E5%B7%A5%E8%B5%84%E5%AE%9E%E6%97%B6%E8%AE%A1%E7%AE%97%E5%99%A8-%E4%B8%8A%E7%8F%AD%E6%91%B8%E9%B1%BC%E6%97%A5%E6%8A%A5/id6757694225)、[牛马计时器](https://apps.apple.com/cn/app/%E7%89%9B%E9%A9%AC%E8%AE%A1%E6%97%B6%E5%99%A8-%E4%B8%8A%E7%8F%AD%E6%91%B8%E9%B1%BC%E5%8A%A9%E6%89%8B/id6748200930?platform=watch)、[DoneAt](https://apps.apple.com/cn/app/doneat-%E4%B8%8B%E7%8F%AD%E5%80%92%E8%AE%A1%E6%97%B6/id6802803318)与[HoursTracker](https://apps.apple.com/us/app/hours-tracker-time-tracking/id336456412)（均访问于 2026-10-13）。

机会来自两个尚未被同一产品解决的问题：**“钱算不明白”与“人下班了，脑子没有下班”。** Sunsama 和 Shutdown Ritual 已验证“结束一天”可以被设计成主动流程而非倒计时归零；Finch、Forest 和 How We Feel 则提供了陪伴角色、可见成长与精细情绪命名的机制参考，但这些机制不能直接证明对中国职场人有效，必须进行本地化验证。([Sunsama](https://www.sunsama.com/features/daily-planning-and-shutdown)；[Shutdown Ritual](https://apps.apple.com/sa/app/shutdown-ritual-workday-wrap/id6757130564)；[Finch](https://finchcare.com/about-finch)；[Forest](https://forestapp.cc/)；访问于 2026-10-13)

中国用户的工作时长和边界问题使“帮用户收工”比“激励用户多工作”更符合责任边界。国家统计局公布 2025 年全国企业就业人员周平均工作时间为 **48.6 小时**，并明确实际工作时间不含午休；产品因此不能从日历跨度推断计薪时间，必须询问休息是否计薪。([国家统计局：2025 年经济运行数据](https://www.stats.gov.cn/sj/zxfb/202601/t20260119_1962330.html)；[工作时长口径答复](https://www.stats.gov.cn/hd/lyzx/zxgk/202412/t20241206_1957667.html)；访问于 2026-10-13)

### 1.2 产品机会判断

| 判断 | 证据 | 产品含义 |
|---|---|---|
| “实时跳钱”已商品化 | 多个中文竞品均有实时收入、倒计时、小组件 | 不能继续以大数字本身作为唯一卖点 |
| 用户会追问真实性 | 评论集中请求夜班、大小周、跨日、午休、加班与累计修正 | 计算解释、历史版本与纠错必须进入 P0 |
| 奖金确定性是明显空白 | 竞品多为年奖金字段或手动收入 | 用“预计—应计—锁定—到账”建立专业壁垒 |
| 情绪价值需要仪式而非语录 | Finch/Forest/Sunsama 的闭环由行动、反馈、收口构成 | 设计开工状态、工作中低频陪伴、日终封账、周度回看 |
| 隐私是购买理由 | 多个竞品把不收集/仅本地作为卖点；锁屏又扩大肩窥面 | 把隐私做成默认架构、可视状态和发布闸门 |
| 轻工具强订阅会被反感 | 直接竞品价格集中在低价买断或低价订阅 | 准确计算与隐私永久免费，收费卖深化价值而非解锁信任 |

### 1.3 核心假设

1. 用户愿意为“算清楚 + 收好情绪”每天花 1 分钟，但不愿每天维护复杂账簿。
2. 固定月薪用户看重即时慰藉和奖金进度；时薪/排班用户更看重不漏工时和班次结算。
3. 把不确定收入从主金额中分离，会提高信任，即使数字看起来更少。
4. 奖励准点下班、完整休息和主动纠错，比奖励连续上班更符合长期品牌价值。
5. “无账户可完整使用、默认不上传”能提高首次录入真实薪资的意愿。

这些是假设而不是已验证事实。进入公开测试前须完成 12–15 人问题访谈、三版原型测试和 30 个计算边界案例走查。

## 2. 产品愿景、定位与边界

### 2.1 愿景与定位

**愿景：**让每一段劳动都有清楚的价值归属，也让每一个下班时刻真正结束工作。

**定位：**面向个人劳动者的本地优先劳动价值账本与下班情绪仪式；比工资计算器更懂情绪，比情绪工具更懂钱。

**一句话价值主张：****把今天的付出算清楚，然后安心下班。**

**核心品牌承诺：**

- 算得清：班次、加班、奖金、提成与扣款逐项解释。
- 分得开：预计、应计、锁定、到账绝不混为“已赚”。
- 收得住：下班不是数字归零，而是一个能完成的收口动作。
- 藏得好：默认本地、默认遮罩、默认脱敏分享。
- 不评判：不把疲惫解释成懒惰，不用加班换成就。

### 2.2 设计原则

1. **事实、规则、情绪三层分离。** 原始工时事实不可被文案层改写；规则有版本；情绪层只解释和陪伴。
2. **确定性高于爽感。** 仅“已锁定”或用户明确选择的劳动价值估算进入首页实线大数字；概率收入用浅色、区间或“奖金天气”显示。
3. **一眼能看，一层能懂。** 首页只放今天；点开任何金额都能看到公式、来源、状态和最近修改时间。
4. **隐私默认值即产品立场。** 无账号、无第三方分析、锁屏不显金额、分享不带金额。
5. **帮助结束，不鼓励硬撑。** 对休息和准点下班给正反馈，对加班只记录和提醒确认，不庆祝。
6. **轻入口、渐进专业。** 两分钟内首次看到结果，复杂奖金和提成向需要的人逐层展开。
7. **诚实表达边界。** 所有金额均为个人记录或估算，不宣称替代工资单、考勤、税务申报或劳动争议证据。

### 2.3 明确不做什么

- 不做企业考勤、排班管理、绩效排名或雇主端后台。
- 不向雇主、广告平台、数据经纪商出售或共享工资、工时、公司与情绪数据。
- 不做公开工资排行榜、好友收入比较、连续加班 streak 或“多工作养活宠物”。
- 不自动读取钉钉、企业微信、定位、通讯录或健康数据；首版不做自动定位打卡。
- 不承诺“法律应得工资”“精确到手收入”或“可直接用于仲裁”。
- 不提供心理诊断、治疗建议或保证改善焦虑/抑郁。
- 不默认让 AI 阅读用户吐槽或工资条；未来如有，必须本地优先、逐次授权、单独评审。
- 不在首版建立账号、自建云同步、公开主页或可追踪分享链接。

## 3. 用户分层、JTBD、场景与痛点

| 用户层 | 典型特征 | 核心 JTBD | 高频场景 | 主要痛点 | 优先级 |
|---|---|---|---|---|---|
| A 固定月薪白领 | 固定工作日，奖金占比不一，偶有加班 | “让我知道今天的劳动值多少钱、奖金走到哪，也提醒我到点收工” | 通勤开工、午休、临时加班、年终奖预测、日终封账 | 月薪按秒只是平均值；加班/奖金说不清；下班仍反刍 | P0 |
| B 时薪/兼职/服务业 | 班次变化、按小时结算、无薪休息 | “让我不漏记班次，结束即知道该收多少” | 一键开班、休息、跨午夜、调班、核对工资 | 忘记停表、休息口径、不同费率、跨日错误 | P0 |
| C 销售/顾问/主播 | 底薪 + 提成 + 回款/退单 | “让我分清已做业绩、已锁定提成和可能到账金额” | 达标预测、阶梯提成、退款冲回、周期复盘 | 阶梯规则复杂；概率收入被当实收；回款滞后 | P1 |
| D 轮班/制造/护士/物流 | 夜班、节假日、综合工时、补休 | “让我按真实班次留下一份可核对的私人记录” | 跨午夜、轮班、法定日、休息日、补休 | 规则地区化、法律风险高、排班录入繁琐 | P1/P2 |
| E 高隐私/无金额用户 | 不愿输入真实工资，只想倒计时和收工 | “不用交出隐私，也能把今天关掉” | 价值点、等级、区间、情绪签到、封账 | 害怕同事/家人看到；对云端和分析不信任 | P0 |

### 3.1 关键 JTBD 语句

- 当我开始工作时，我想用最少操作确认今天的班次，以便不再靠记忆补账。
- 当我工作到一半时，我想看见时间正在换回什么，而不是被倒计时催得更焦虑。
- 当我被要求临时加班时，我想把它明确标成待确认的加班，以便不让额外付出消失。
- 当奖金规则复杂时，我想看到目标、应计、锁定与到账的差异，以便不把希望当现金。
- 当我下班时，我想核对金额、放下一件事并完成一个明确动作，以便心理上也离开工作。
- 当我分享时，我想表达“今天辛苦了”但不暴露薪资、公司或精确作息。
- 当我担心隐私时，我想知道每类数据在哪里、谁能看到、如何彻底删除，而不是只读一页法律文本。

### 3.2 成功场景

首要成功场景不是用户打开 App 更久，而是：早上 5 秒确认班次；午休一键暂停；下班 60 秒内核对并封账；第二天无需重设；月底能解释“预计、应计、锁定、到账”为何不同；任何外部表面默认看不到工资。

## 4. 竞品矩阵与差异化

| 产品 | 实时工资/倒计时 | 排班与加班 | 奖金/提成 | 情绪机制 | 隐私 | 价格信号 | 主要启示 |
|---|---|---|---|---|---|---|---|
| 打工喵 | 强 | 中，评论仍请求夜班/大小周 | 年奖金/简单收入 | 愿望、日报、评级、猫咪 | 无注册；仍声明分析数据 | ¥6/月、¥38/年、¥48 永久 | 情绪表达有效，但不能替代准确性 |
| 牛马计时器 | 强 | 强，含轮班/请假/休息 | 手动奖金/副业 | 宠物、目标、倒计时 | 声明不收集，可 iCloud | ¥6/月、¥28/年、¥48 永久 | 功能宽度已高，基础功能不再构成壁垒 |

| 开薪 | 强 | 中 | 简单 | 结算战报、语录、徽章 | 多表面隐藏金额，但声明或收集财务信息 | 一次性 ¥6 | 隐私模式必须覆盖所有表面 |
| MotivCount | 强 | 中 | 年奖金字段 | 电子宠物 | 声明不收集 | 部分组件一次性 ¥8 | “奖金字段”不等于奖金管理 |
| 摸鱼/实时薪资 | 强 | 中 | 弱 | 拉闸、封条、清算单、强文案 | 声称 AES、分享打码 | 未确认 | 下班仪式已被验证为可理解概念 |
| HoursTracker | 中 | 很强 | 加减项 | 弱 | Face ID/Touch ID | 成熟工具 | 专业工资核对的能力上限 |
| Wage Tracker / Checkout | 中 | 强 | 佣金、税率、Tips、工资单差异 | 弱 | 依产品而异 | 未统一 | 可解释收入与收据化明细值得借鉴 |
| Finch / Forest | 无 | 无 | 无 | 很强：伙伴、成长、可见资产 | 本地/选择性数据机制各异 | 订阅/买断 | 情绪价值来自闭环，不是随机文案 |
| Sunsama / Shutdown Ritual | 无 | 工作计划 | 无 | 强：主动关闭一天 | 非工资产品 | 订阅/买断 | “下班”应成为有起点、有完成态的流程 |

资料来源与访问日期见附录；应用商店隐私标签均属开发者自报，不视为独立安全审计。

### 4.1 可守住的差异化

1. **劳动价值双账本**：同时保存“工时事实”和“收入状态”，不是简单秒表。
2. **奖金确定性引擎**：把目标奖金率、个人系数、公司系数、出勤系数、提成与回冲统一建模。
3. **下班结算协议**：核对—命名—放下—封账，而非静态战报。
4. **负责任的情绪价值**：奖励边界与休息，不把加班设计成成长燃料。
5. **可验证的本地隐私**：隐私不是开关，而是存储、外部表面、分享、遥测和删除的系统承诺。

## 5. 薪酬引擎：定义、公式与状态

### 5.1 三层模型

**事实层**保存原始记录：班次开始/结束、休息段、工作日类型、项目、件数、销售额、回款、退款、用户确认记录。事实只追加修订，不因规则变化被覆盖。

**规则层**保存版本化规则：薪资方案、生效区间、结算周期、计薪口径、加班基数/倍率、奖金/提成公式、津贴扣款、舍入方式。规则修改必须选择“仅今天 / 从某日生效 / 重算历史”，并生成新版本。

**展示层**把结果翻译为首页大数字、奖金天气、结算清单、目标进度和情绪文案。展示层不得改写事实或把不确定收入包装成已到账。

### 5.2 金额状态词典

| 状态 | 定义 | 进入条件 | 首页表现 | 可否手动回退 |
|---|---|---|---|---|
| **预计 Estimated** | 基于计划、目标或情景假设计算，条件尚未发生或未核实 | 创建奖金目标、排班计划、概率情景 | 浅色/区间/虚线，不计入“已锁定”大数字 | 是 |
| **应计 Accrued** | 对应劳动或业绩已经发生，按当前规则累计，但公司尚未确认 | 班次结束、里程碑完成、销售发生 | 独立显示“已付出、待确认” | 是，需留痕 |
| **锁定 Locked** | 金额或资格已被工资条、公司确认、回款或用户可靠凭据确认，但钱尚未到账 | 用户明确确认并记录依据 | 实线金额，可进入待收总额 | 是，需原因 |
| **到账 Paid** | 用户确认实际收到资金 | 手动标记或未来本地对账确认 | 进入现金到账统计 | 是，需反向流水而非删除 |

状态流通常为 `预计 → 应计 → 锁定 → 到账`，但允许 `预计 → 锁定`、`应计 → 取消/冲回`。系统绝不根据日期自动把金额设为“到账”。若用户修改规则，已有到账流水不重算；以冲正 + 新流水保留审计链。

### 5.3 时间与班次规则

定义：

- `shift_duration = end_timestamp - start_timestamp`
- `paid_break_minutes = Σ 标记为计薪的休息段`
- `unpaid_break_minutes = Σ 标记为不计薪的休息段`
- `excluded_minutes = 用户手工排除的非工作区间`
- `paid_minutes = shift_duration_minutes - unpaid_break_minutes - excluded_minutes`
- `worked_minutes = shift_duration_minutes - 所有休息分钟`，用于工作时长健康提示，不等同计薪分钟。

要求：

- 开始、结束均使用带时区绝对时间；本地日仅用于展示。
- 结束早于开始时，不猜测输入错误；提示“是否为次日结束”。确认后标记跨午夜。
- 跨午夜班次按规则生效时点和自然日边界切段，分别判断工作日/休息日/法定节假日。
- 夏令时地区使用实际经过秒数，不用“结束时刻减开始时刻”的墙上时间硬算；中国大陆首发仍保留通用实现。
- 多段班允许一天多个 shift；重叠班次禁止静默重复计薪，保存前显示冲突。
- 忘记下班超过计划结束 4 小时进入异常态：停止首页金额继续增长，显示“待确认”，不得默认累计整夜收入。
- 休息可预设也可临时开始；每段必须有 `paid/unpaid` 属性，首次设置不做法律判断，只问用户公司口径。

### 5.4 固定月薪/年薪

固定薪资需要区分“工资周期预计收入”和“今日劳动价值分摊”，避免暗示固定月薪按缺勤分钟实时扣减。

设：

- `F_period`：结算周期固定工资；月薪直接取月薪，年薪按用户选择的发薪期拆分。
- `S_period`：本周期计划计薪分钟总数，来自排班或用户选择的折算口径。
- `M_today`：今日正常计薪分钟，不含另计加班分钟。
- `base_alloc_today = F_period × M_today / S_period`。

首页称其为“**今日劳动价值估算**”，而不是“公司今天欠你的工资”。工资周期页的固定工资预计值仍为 `F_period`，除非用户录入请假/缺勤扣减规则。可选口径：

1. 公司实际排班口径：周期内计划计薪分钟之和；推荐。
2. `21.75 × 每日标准小时` 参考口径：用于标准工时下的加班基数折算参考。
3. 纯情绪平均值：用户自定义每月工作天数/小时；醒目标“非工资核算口径”。

不得把奖金、津贴、加班费默认并入加班基数。工作日延时加班参考公式为 `B_ot ÷ 21.75 ÷ 8 × 1.5 × overtime_hours`；休息日无法补休时参考 2 倍；法定节假日参考 3 倍。实际基数受合同、地区和公司规则影响，因此 `B_ot` 必须单独设置并标“用户口径/参考口径”。([上海市人社局](https://rsj.sh.gov.cn/tmsztc_17502/20200617/t0035_1379410.html)，访问于 2026-10-13)

### 5.5 时薪与日薪

**时薪：**

`base_pay = Σ(rate_segment × paid_hours_segment)`

其中 rate segment 可按岗位、班次、时间段或生效日切换。夜班加成可建模为倍率或固定每小时津贴，但默认不把两者重复相加。支持最小计费单位（1/5/10/15/30 分钟）和舍入规则（精确、向下、四舍五入、向上）；结算页必须显示舍入前后差异。

**日薪：**

`day_pay = day_rate × attendance_fraction`

`attendance_fraction` 由用户自定义为整日/半日/按小时比例，默认整日班次完成即 1 日，不擅自按迟到分钟扣减。跨午夜但属于同一排班实例时只计一个班次日；若合同按自然日计费，用户可切换规则。

**计件：**

`piece_pay = Σ(accepted_quantity_i × unit_price_i) + quality_bonus - rejected_or_returned_deduction`

计件验收状态同样使用预计/应计/锁定/到账。

### 5.6 加班、补休与工作日类型

每段加班必须具有 `day_type`：工作日、休息日、法定节假日、自定义；`compensation_mode`：现金、补休、待定；`confirmation_state`：待确认、已确认、已拒绝/取消。

`overtime_pay = overtime_base_hourly × multiplier(day_type) × confirmed_overtime_hours`

默认参考倍率为工作日 1.5、休息日 2.0、法定节假日 3.0，但只在用户选择“标准工时参考”时提供；允许公司自定义且持续显示“自定义口径”。休息日选择补休时，该段先进入“补休余额”，不进入现金加班额；若后续改为现金，以新流水释放金额。综合计算工时和不定时工时首版仅允许“自定义规则”，不做全国通用法律结论；特殊工时制规则差异见[人社部审批办法](https://www.mohrss.gov.cn/xxgk2020/gzk/gz/202112/P020211229609908265429.pdf)（访问于 2026-10-13）。

### 5.7 奖金引擎

奖金对象字段：名称、周期、奖金基数、目标率/目标月数、个人系数、公司系数、出勤系数、概率/情景、应计方法、锁定条件、预计发放日、状态、依据备注、规则版本。

**固定额：** `bonus_target = fixed_amount`

**固定月数：** `bonus_target = bonus_base_monthly × target_months`

**目标奖金率：** `target_bonus = bonus_base_period × target_bonus_rate`

**系数奖金：**

`bonus_scenario = target_bonus × personal_coefficient × company_coefficient × attendance_coefficient`

个人系数和公司系数不得默认都为 1 并悄然计入主金额；未公布时显示“待输入”。情景预测至少包含：

- 保守：用户填写的较低系数组合；
- 目标：制度目标系数；
- 冲刺：上限或高绩效系数组合。

示例：奖金基数 ¥120,000，目标奖金率 15%，个人系数 1.1，公司系数 0.8，则目标情景为 `120,000 × 15% × 1.1 × 0.8 = ¥15,840`。它在公司确认前仍是“预计”，不能进入已锁定总额。

**应计方法：**

- 直线应计：`accrued_bonus = scenario_bonus × elapsed_eligible_days / eligible_days_in_period`。
- 业绩应计：`accrued_bonus = formula(current_confirmed_performance)`。
- 里程碑应计：完成每个里程碑后释放对应权重。

应计表示劳动或业绩已发生，不代表雇主已确认。首页以“本期奖金天气”显示：已锁定金额为晴区，应计待确认为多云区，未发生目标为远期区；点击后回到严谨公式和状态。

### 5.8 提成引擎

支持两类核心阶梯，必须在 UI 中明确选择并用样例预览：

**边际累进（marginal）：**

`commission = Σ max(0, min(performance, upper_i) - lower_i) × rate_i`

例：0–10 万 2%，10–20 万 3%，20 万以上 5%，销售 25 万，则 `10万×2% + 10万×3% + 5万×5%`。

**达标后全额跳档（cliff/retroactive）：**

`commission = total_eligible_performance × rate(highest_reached_tier)`

同样 25 万若达到 5% 档，则为 `25万×5%`。系统保存规则时必须展示两个结果差异，防止选错模型。

附加能力：单一比例、品类费率、团队分摊、保底、封顶、回款确认、退款冲回。提成默认以“已回款且过退货期”的用户规则进入锁定；销售发生可进入应计。退款不删除原流水，而新增负向冲回：`net_commission = positive_commission - clawback`。

### 5.9 津贴、补贴、成本与扣款

**收入项：**餐补、交通、夜班、高温、驻场、里程、Tips、自定义津贴；可按班次、小时、日、月或事件计算。

**工作成本：**通勤、工作餐、装备、平台抽佣等，只用于“净劳动价值”视图，不默认当作工资扣款。

**扣款项：**事假、缺勤、福利、自定义固定扣款、社保、公积金、个税估算。任何扣款规则都显示来源为“用户输入/工资条反推/政策模型”。MVP 不提供城市级精确社保公积金；个税与全年一次性奖金政策有时效性，必须带政策版本和有效期。当前符合条件的全年一次性奖金单独计税政策延续至 2027 年 12 月 31 日，后续不可写死。([国家税务总局](https://jiangsu.chinatax.gov.cn/art/2023/8/28/art_8349_432405.html)，访问于 2026-10-13)

### 5.10 日终与周期结算公式

`今日已锁定价值 = 正常收入分摊 + 已确认现金加班 + 已锁定奖金/提成 + 已锁定津贴 - 已锁定扣款 - 今日直接工作成本`

`今日应计待确认 = 应计未锁定加班 + 应计奖金/提成 + 待确认津贴 - 待确认扣款`

`本周期预计 = 固定薪资预计 + 预计可变收入 + 已知津贴 - 预计扣款`

结算页分栏显示，不提供一个混合“你今天赚了 ¥X”掩盖确定性。所有金额支持税前/税后标签；未配置税后模型时只显示税前。币种转换首版不做自动汇率；不同币种分账显示。

### 5.11 精度、舍入与免责声明

- 内部金额使用十进制定点数，以货币最小单位存储，不用二进制浮点直接结算。
- 时间以秒记录、按规则到分钟/计费单位舍入；只在最终展示层按币种小数位舍入。
- 每笔结果保存公式版本、输入快照、时区、生效规则、创建/修改时间。
- 固定显示：“本结果是基于你提供信息的个人估算，不是工资支付凭证、税务申报或法律意见。”
- 工时导出可作为个人记录，但不得声称其单独构成劳动争议证据；法院会综合聊天记录、工作内容、频率、时长等判断。([最高人民法院](https://www.court.gov.cn/shenpan/xiangqing/423922.html)，访问于 2026-10-13)

### 6.1 一级信息架构

| 一级入口 | 核心任务 | 关键内容 |
|---|---|---|
| 今天 | 开始、查看、暂停、加班、收工 | 当前班次、锁定/应计价值、下班倒计时、奖金天气、情绪入口 |

| 我的 | 管理规则与隐私 | 薪资方案、排班、奖金提成、隐私保险箱、主题人格、导出/删除 |

Web 在宽屏上使用左栏导航，移动 Web 与 iPhone 使用四栏底部导航。复杂设置采用逐层展开，不把财务表单堆到首页。

### 6.2 首次激活：2 分钟看到价值

1. 隐私承诺：“你的工资，只给你看。默认本机计算，不注册、不上传；锁屏和分享默认不显示金额。”
2. 选择模式：月薪、时薪、日薪、暂不填金额。
3. 输入最少字段：金额/区间、工作日、开始/结束、休息是否计薪。
4. 预览：“按当前口径，今天劳动价值估算约 ¥X；下班还有 Y。”
5. 选择陪伴语气：温柔、冷幽默、直球夸夸、极简；默认极简，可跳过。
6. 开始记录。奖金、税、社保、复杂排班均在结果出现后渐进引导。

验收：新用户中位完成时间 ≤120 秒；任何一步可返回；选择“不填金额”仍可用完整计时与仪式；未授权通知不阻断使用。

### 6.3 工作中

- 系统按计划建议班次，用户确认后开始；不能因到点自动认定已经上班。
- 首页主卡默认显示下班倒计时与用户选择的隐私级别。金额每秒视觉更新来自“开始时间戳 + 规则重算”，不依赖后台每秒运行。
- 高频操作：开始/结束休息、标记临时加班、老板来了、被气到了、收工。
- 达到目标时仅低频提示“今天已覆盖通勤/午饭/旅行基金 2%”；用户可关闭。
- 到计划下班时间，CTA 从“继续记录”切换为“收工结算”；继续工作必须选择“标记加班/延长计划/明天再做”，不静默延长。

### 6.4 奖金预测

入口为“我的 > 奖金与提成”或首页奖金天气卡。流程：选奖金类型 → 填基数与目标率/月数 → 填个人/公司/出勤系数 → 定义应计方式和锁定条件 → 查看保守/目标/冲刺 → 保存。缺少系数时结果显示“待补全”，不把空值默认为 1。用户可在发放前更新系数，并选择是否重算尚未锁定部分；到账后录入实际金额，系统生成预测偏差而不覆盖历史。

### 6.5 下班结算协议：60 秒收口

1. **核对事实（≤20 秒）**：开始/结束/休息；异常跨日或重叠先解决。
2. **看清价值（≤15 秒）**：已锁定、应计待确认、预计三栏；点任意项看公式。
3. **命名今天（≤10 秒，可跳过）**：从疲惫、麻木、烦躁、委屈、平静、松一口气、有掌控感等词中选一个。
4. **放下一件事（≤10 秒，可跳过）**：“留给明天 / 粉碎一句吐槽 / 什么也不写”。
5. **封账（≤5 秒）**：滑动拉闸或盖章，轻触觉反馈，角色摘工牌；页面明确“今天到这里就够了”。
6. **结果**：生成劳动结晶和默认零金额分享卡；可直接退出，不强迫分享或写日记。

封账后再次开启工作模式，先问：“今天已经结算。继续这段要记为加班，还是明天再开始？”避免无意识复工。

### 6.6 隐私模式与分享

首页全局“眼睛”按钮切换直显/伪装/隐身；长按或 Face ID 可临时显示 15 秒。老板来了快捷动作立即切换为中性番茄钟/天气式进度，不显示工资、公司或奖金。分享流程固定为：选择模板 → 默认全字段关闭 → 逐项开启 → 本地预览 → 必要时 Face ID → 系统分享。无公开链接，无服务器生成图；图片元数据不含原始字段。

## 7. 情绪价值系统与负责任游戏化

### 7.1 三段式回血循环

**开工前：选择被陪伴的方式。** 只问“今天电量几格？”和“今天想安静 / 想被夸 / 允许吐槽”，均可跳过。低电量不会降低得分或触发劝努力。

**工作中：让价值可见但不催促。** 角色缓慢变化；每 90–120 分钟优先提醒喝水、伸展、离屏，不以“距离目标还差很多”施压。金额换算默认允许用户选择房租、旅行、自由时间、家人礼物等长期目标，不只推奶茶消费。

**下班时：完成情绪收口。** 以事实核对开始，以“今天到这里就够了”结束；情绪记录只服务本人，不生成诊断和企业洞察。

### 7.2 具体模块

| 模块 | 行为 | 奖励/反馈 | 禁止机制 |
|---|---|---|---|
| 劳动结晶 | 每次封账生成一枚视觉资产 | 颜色来自自选情绪，纹理由工时结构决定，光泽来自休息完整度 | 加班越久越稀有 |
| 下班结界 | 封账后当天工作态关闭 | 锁屏显示“今天已结算” | 用 streak 惩罚重新开始 |
| 边界成就 | 准点收工、完整午休、主动纠错、周末不工作 | 皮肤、故事、桌面小物 | 连续上班、深夜工作成就 |
| 工作碎片回收站 | 写一句吐槽并选择粉碎/封存/未来再看 | 动画与本地保存 | 自动上传或 AI 默认分析 |
| 价值罐子 | 将今日价值分配到生活/未来/自由/家人 | 月末人生返还图 | 商城式消费诱导 |
| 奖金天气 | 用晴/云/远期表达确定性 | 降低虚假精确感 | 把概率收入放进现金余额 |
| 一分钟回血 | 呼吸、伸展、喝水、离屏、写一句 | 完成即结束，无评级 | 医疗疗效承诺 |

### 7.3 文案规则

采用“**事实—承认—边界—选择**”四段结构：

> 今天记录了 8 小时 12 分。累不是不够努力，是身体也在记账。计划工作已经结束。现在封账，还是补记一段已发生的加班？

规则：

- 先说可验证事实，不捏造共情。
- 允许疲惫、烦躁和无感，不把负面情绪道德化。
- 不使用“再坚持一下”“离目标还差”“别人都在努力”等推动加班的话。
- “牛马、摸鱼、发疯”等自嘲仅作为用户主动下载的语气包；默认只称“你”。
- 不以金额高低决定赞美强度；高薪与低薪得到同等尊重。
- 文案不给诊断，不说“你抑郁了”“这个练习可以治疗焦虑”。数字心理健康干预的研究结论仍受证据质量限制。([相关综述](https://pubmed.ncbi.nlm.nih.gov/39854722/)，访问于 2026-10-13)

### 7.4 护栏

- 加班不会增加宠物生命、稀有度、排行榜或连续记录。
- 休息、未工作、情绪低落不会失去资产。
- 所有情绪模块可关闭；关闭后不出现空洞提醒。
- 22:00–08:00 默认不发工作提醒；用户主动夜班可单独设置。
- 若一周异常超长班次增加，提示检查忘记停表和休息，而不是表扬投入。
- 分享只传播边界、心情或目标进度，不形成工资攀比。

## 8. 隐私威胁模型与双端隐私设计

### 8.1 威胁模型

| 威胁 | 攻击/暴露面 | 影响 | P0 控制 |
|---|---|---|---|
| 肩窥与同事借机 | 已解锁界面 | 暴露薪资、奖金、作息 | 一键遮罩、老板来了、应用锁、临时显示超时 |
| App Switcher 快照 | iOS 后台卡片 | 金额长期可见 | `scenePhase` 非 active 时用中性遮罩并移除敏感视图 |
| 锁屏/常亮屏 | Widget、Live Activity、通知 | 无需解锁即看到工资 | 默认仅倒计时；敏感视图 `privacySensitive()`；通知无金额 |
| 录屏/投屏/会议共享 | 系统屏幕捕获 | 实时传播敏感信息 | 监听 `UISceneCaptureState`，自动遮罩并提示 |
| 单张截图 | 本机相册/转发 | 无法可靠阻止 | 截图后提醒；提供一键无金额分享模式，不声称禁止截图 |
| 丢失设备 | App container、备份 | 离线读取 | Complete Data Protection + AES-GCM + Keychain 密钥 |
| Web XSS/恶意依赖 | 同源脚本、Web Storage | 批量读取/篡改 | 默认会话模式、不用 localStorage 明文、严格 CSP、无第三方脚本 |
| 分析/崩溃 SDK | 事件属性、breadcrumb、截图 | 工资或自由文本外传 | 首版第三方分析 SDK 为 0；事件白名单；发布抓包 |
| 导出/分享临时文件 | Files、剪贴板、分享扩展 | 明文残留 | 再认证、风险提示、Complete Protection、结束/失败均删除 |
| 备份与换机误解 | iCloud Backup/手动备份 | 以为“仅本机”却上云，或换机丢失 | 清晰区分严格本地/系统备份/加密导出 |

### 8.2 iOS 存储与认证规范

- 工资、规则、工时、公司别名、情绪与备注从 `UserDefaults` 迁移到版本化加密数据文件或数据库。
- 敏感文件位于 `Library/Application Support`，主库、WAL/SHM、临时文件均设 `NSFileProtectionComplete`。
- 首次运行生成随机 256-bit 对称密钥；敏感 payload 使用 CryptoKit AES-GCM 认证加密，每次写入新 nonce。
- 密钥只存 Keychain，建议 `kSecAttrAccessibleWhenUnlockedThisDeviceOnly`；开启应用锁后用 `.userPresence`。不得宣传“整库存进 Secure Enclave”，准确表达为“系统数据保护和钥匙串保护密钥”。([Apple Keychain](https://developer.apple.com/documentation/security/keychain-services)；[AES.GCM](https://developer.apple.com/documentation/cryptokit/aes/gcm)；访问于 2026-10-13)
- Face ID/Touch ID 仅返回认证结果，应用不接触生物特征；冷启动和超时回前台认证失败时不渲染敏感数据。
- 进入 inactive/background 前显示遮罩并清除可复用解密模型；可选锁定超时为立即、1 分钟、5 分钟。
- 首版无账号、无自建服务器。可选 iCloud 放到 P1，默认关闭，并单独说明字段、备份、恢复、关闭与删除。

### 8.3 Web 隐私规范

- 默认“仅本次使用”：敏感数据仅在内存中，关闭标签页即清除。
- 删除现有 `localStorage['realtime-salary-profile']` 明文迁移路径；升级时先读旧值、提示用户迁移或删除，成功后擦除旧 key。
- 用户主动选择“记住此浏览器”时，用口令派生密钥加密后保存到 IndexedDB；口令和密钥不持久化。明确说明：网页解锁后无法抵御当前源中的恶意脚本，长期敏感记录推荐原生 App。
- 生产环境 HTTPS，敏感响应 `Cache-Control: no-store`；Service Worker 不缓存用户状态。
- 严格 CSP 基线：`default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self' data:; connect-src 'self'; font-src 'self'; object-src 'none'; base-uri 'none'; frame-ancestors 'none'; form-action 'self'`；不使用远端脚本、`unsafe-eval` 或未经处理的 `innerHTML`。
- 依赖锁定、漏洞扫描和输入转义进入 CI。OWASP 明确不建议在 `localStorage` 保存敏感信息，因为同源脚本和 XSS 可读取全部存储。([OWASP HTML5 Security](https://cheatsheetseries.owasp.org/cheatsheets/HTML5_Security_Cheat_Sheet.html)，访问于 2026-10-13)

### 8.4 外部表面处理

- **Widget/Live Activity**：默认只显示“距离收工 01:23”；金额开关独立、默认关闭，开启前预览暴露风险；锁定时使用 `privacySensitive()` 或整体占位。([WidgetKit](https://developer.apple.com/documentation/widgetkit/creating-a-widget-extension)；[Live Activities HIG](https://developer.apple.com/design/human-interface-guidelines/live-activities)；访问于 2026-10-13)
- **通知**：标题与正文不含工资、奖金、公司名或精确作息；示例“该收工啦”“今天的回血可以封账了”。
- **App Switcher**：快照中不得出现金额、公式、公司名、曲线或吐槽。
- **录屏/镜像**：自动切隐身，允许用户明确操作临时显示；记录设置变更，不记录捕获内容。
- **截图**：无法可靠阻止，截图后提示“已截图，分享前建议使用脱敏卡”；不自动读取相册。
- **老板来了**：首页、Widget 与当前 Live Activity 同步切为中性外观；恢复需长按或认证；快捷动作不得暗示其可防止系统级取证。

### 8.5 遥测白名单

首版默认无第三方分析 SDK。若灰度阶段经用户明确选择加入，只允许以下枚举/布尔/分桶参数：

| 事件 | 允许参数 | 禁止参数 |
|---|---|---|
| `onboarding_completed` | 薪资模式枚举、耗时桶、是否无金额模式 | 金额、城市、公司、精确时间 |
| `timer_started` | 平台、是否计划班次 | 开始时间戳、岗位、工资 |
| `break_toggled` | paid/unpaid 枚举 | 精确分钟、班次详情 |
| `settlement_opened/completed` | 用时桶、是否修正、是否跳过情绪 | 金额、情绪词、备注 |
| `formula_explained` | 模块枚举 | 输入值与结果 |
| `privacy_mode_changed` | 直显/伪装/隐身枚举 | 生物认证结果细节 |
| `share_generated` | 模板、是否含金额（布尔） | 图片、金额、公司、文本 |
| `data_deleted` | 删除范围枚举、成功与否 | 被删内容、稳定用户 ID |

所有新增字段默认构建失败，须经隐私评审加入 schema allowlist。禁止自由文本、金额、奖金率、系数、时间表、公司名、精确时间戳、广告 ID、稳定跨应用 ID、页面截图和导出内容。App Store 聚合指标优先于自建分析。

### 8.6 导出、备份与删除

- 导出支持 CSV、JSON 与加密备份；明文导出前再次认证，并提示“任何拿到文件的人都能读取”。
- 临时导出文件设 Complete Data Protection、排除备份，分享完成、取消或失败后均删除。
- 严格本地模式：敏感库 `isExcludedFromBackup = true`，每次保存后重新断言；换机依赖用户加密导出。
- 标准本地模式：允许系统备份，界面明确“开发者不接收；是否进入 iCloud Backup 由系统设置决定”。
- 删除分三层：清空工资配置、清空情绪/吐槽、彻底抹除。彻底抹除同时删除主库、WAL/SHM、旧 UserDefaults/localStorage、Keychain 密钥、缓存、临时文件、通知、Widget 与 Live Activity 状态。
- 删除离线可完成、不要求注册或联系客服；完成页列出已删除项。

### 8.7 隐私发布硬门槛

- 默认链路工资相关字段对开发者/第三方出站：**0**。
- 生产包第三方追踪域：**0**；首版第三方分析 SDK：**0**。
- 默认在 App Switcher、锁屏、通知、Widget、Live Activity 暴露金额：**0 处**。
- 容器、日志、缓存与 Web Storage 的敏感明文扫描命中：**0 条**。
- 彻底删除后的敏感文件、Keychain、组件与通知残留：**0 条**。
- 遮罩、应用锁、锁屏显示、导出、彻底删除均在设置首页两步内到达。

## 9. 功能需求与验收标准

### 9.1 P0：完成“今天闭环”

#### FR-P0-01 薪资与排班设置

**用户故事：**作为月薪、时薪或无金额用户，我希望两分钟内完成最少设置并看到今天结果。

**交互：**分步选择薪资类型、金额/区间、工作日、上下班、休息计薪、隐私级别；复杂项稍后设置。

**数据：**SalaryPlan、ScheduleTemplate、BreakRule、PrivacyPreference、RuleVersion。

**边界：**0/负数拒绝；金额上限只做异常提示不武断拦截；结束早于开始询问跨日；24 小时或重叠班次提示；无金额模式用价值点。

**验收：**中位完成 ≤120 秒；所有字段可返回修改；结果明确显示口径；首次未设置奖金不出现 `NaN/0 奖金`；Web 与 iOS 共享 20 组基础测试向量结果完全一致。

#### FR-P0-02 今日计时与实时价值

**用户故事：**作为上班中的用户，我想随时知道班次状态、距下班多久及当前确定性收入。

**交互：**开始、暂停/休息、继续、临时加班、收工；回到前台按时间戳即时重算。

**边界：**系统时间变化、跨时区、杀进程、重启、忘记停止、重复点击、多个标签页/场景冲突。

**验收：**前台显示与事实时间误差 <1 秒；杀进程后恢复同一班次；后台无需每秒执行；超过计划结束 4 小时转待确认且不继续无上限增长；重复操作幂等。

#### FR-P0-03 休息与基础加班

**用户故事：**作为有午休或临时加班的用户，我希望分清工作时长、计薪时长和加班状态。

**交互：**一键开始休息，默认沿用 paid/unpaid 规则；到点后选择收工、加班或延长计划。

**边界：**休息跨午夜、重叠休息、休息未结束、休息长于班次、法定节假日手工修正。

**验收：**结算同时显示班次跨度、实际工作、计薪、休息和加班分钟；工作日/休息日/法定日分栏；未确认加班不进入锁定金额。

#### FR-P0-04 基础奖金

**用户故事：**作为有年终奖或目标奖金的用户，我希望看到目标率、当前应计、锁定与到账的区别。

**交互：**支持固定额、固定月数、薪资比例、目标率 × 个人系数 × 公司系数；提供三情景。

**边界：**系数缺失、系数为 0、超出常见范围、规则中途变更、离职/不满足出勤、实际到账不同。

**验收：**缺系数不得默认计入；示例公式结果准确；状态迁移有留痕；到账不由日期自动触发；已到账记录修改生成冲正；首页不把预计奖金并入锁定大数字。

#### FR-P0-05 下班结算协议

**用户故事：**作为结束一天的用户，我想在 60 秒内核对、标记情绪并真正收工。

**交互：**五步流程可逐步跳过非必要情绪项；财务核对必经但一屏完成。

**边界：**忘记开始/结束、异常长班次、跨日、无金额模式、零收入、休假日误启动、重新开工。

**验收：**80% 可用性测试参与者在无帮助下 ≤60 秒封账；封账生成不可变结算快照与劳动结晶；再次开工需确认加班或新班次；退出不强迫分享。

#### FR-P0-06 情绪陪伴

**用户故事：**作为疲惫用户，我想被理解而非被催促。

**交互：**四种语气、一次可跳过签到、被气到了、一分钟动作、回收站。

**边界：**用户关闭全部文案、负面词、连续低电量、夜班时段、无情绪选择。

**验收：**关闭后不再推送；无文案把加班、低落或收入高低转为道德评价；全部发布文案经内容审查；负面文案举报可定位到文案版本但不上传用户情绪。

#### FR-P0-07 隐私保险箱

**用户故事：**作为录入真实工资的用户，我希望知道数据存在哪里，并能控制屏幕、导出和删除。

**交互：**直显/伪装/隐身、Face ID、后台遮罩、老板来了、存储状态、导出与删除。

**验收：**满足 8.7 所有硬门槛；冷启动认证取消不显示敏感视图；录屏时自动遮罩；彻底删除重启后无残留。

#### FR-P0-08 可解释账本与 CSV 导出

**用户故事：**作为对数字有疑问的用户，我希望点开任一项看到公式和来源并纠错。

**交互：**结算项抽屉展示事实、规则、公式、状态、版本和修改时间；编辑时选择影响范围。

**边界：**历史规则改变、到账后纠错、删除薪资方案、币种变化。

**验收：**每一分钱可追溯到条目；到账项不静默重算；修改前显示影响记录数量与金额差异；导出带状态和口径标签。

### 9.2 P1：完成“工资周期闭环”

#### FR-P1-01 复杂班次

支持大小周、轮班循环、多段班、跨午夜、临时调班、请假和夜班津贴。验收包括至少 30 个边界案例，跨午夜按规则/自然日正确切段；日历批量编辑不要求逐日配置；排班模板变更不覆盖历史事实。

#### FR-P1-02 提成与里程碑奖金

支持单一比例、边际阶梯、全额跳档、品类费率、团队分摊、回款确认、退款冲回、保底封顶。验收要求保存前展示样例；边际与全额模型测试结果分别正确；退款以负流水追溯原单；预计、应计、锁定、到账统计可对上总账。

#### FR-P1-03 战绩与工资周期

提供周/月/年收入构成、状态迁移、目标偏差、准点下班率、完整休息率与人生返还图。默认不把工作更久定义为更好。验收：图表支持隐藏金额；到账与预计不可堆叠误导；跨周期调薪按生效日拆分。

#### FR-P1-04 iOS 外部表面

Live Activity、锁屏/桌面小组件、Siri/快捷指令提供开始、休息、收工与倒计时。验收：默认无金额；系统锁定、Always-On、灵动岛、StandBy、Apple Watch 镜像逐项真机检查；过期活动自动结束；小组件刷新受限时仍展示正确结束时间而非伪造秒跳。

#### FR-P1-05 加密备份与私有同步

优先提供端到端加密手动备份；iCloud 私有数据库另行评审。验收：恢复前校验完整性与版本；错误口令不泄露部分明文；密钥丢失风险明确；冲突合并不覆盖到账流水；可一键关闭并删除云端副本。

### 9.3 P2：扩展“个人劳动权益”

- 经法律/薪税专业复核的地区化社保、公积金、个税与政策版本中心。
- 工资条本地 OCR 与逐项对账，默认不上传原图。
- 综合计算工时周期、自定义特殊工时、补休余额。
- Apple Watch 快捷班次与收工仪式。
- 无金额好友互相“催下班/休息祝福”；无排名、无收入可见性。
- 可验证开源的跨端计算内核与隐私实现。

P2 的 OCR、云同步、社交或政策模型均需重新做数据流、合规与威胁评审，不能沿用 P0 的“无出站”结论。

## 10. 非功能需求、分析与实验

### 10.1 非功能需求

| 类别 | 要求 | 验收目标 |
|---|---|---|
| 正确性 | Web/iOS 共用公式规范与黄金测试向量 | P0 规则 100% 通过；金额无浮点漂移 |
| 性能 | 冷启动、首页恢复、结算计算 | 主流近 4 年 iPhone 冷启动 P95 <2 秒；前台重算 <100ms；结算 <300ms |
| 可靠性 | 离线完整可用；崩溃恢复 | 核心流程无网络可完成；活动班次恢复成功率 ≥99.9% |
| 安全 | 加密、外部表面、日志、删除 | 8.7 硬门槛全部通过；高危漏洞 0 |
| 可用性 | 首次设置与封账 | 首次设置中位 ≤120 秒；封账中位 ≤60 秒 |
| 无障碍 | 动态字体、VoiceOver、对比度、减少动态效果 | WCAG 2.1 AA 目标；核心路径 VoiceOver 可完成；动画可关闭 |
| 兼容性 | Web 与 iOS | Safari/Chrome/Edge 最近两个主版本；iOS 最低版本由实现评估后冻结 |
| 可维护性 | 规则版本、数据迁移、回滚 | 每版提供迁移测试；旧数据不丢；失败可恢复 |
| 国际化 | 金额、日期、时区 | CNY 首发；币种不混算；跨时区事实不漂移 |

### 10.2 北极星与指标树

**北极星：周有效回血用户数（WERU）**＝一周内至少 3 天完成“开始记录 + 日终结算”，且至少 2 次在结算后选择“比开始时轻松一点/更有掌控感”的用户数。

该指标必须在用户明确加入匿名测量时才可服务端统计；否则在本机展示个人趋势，只用 App Store 聚合指标评估整体。不得以工作时长、加班金额或页面停留时长作为北极星。

**核心指标：**

- 激活：设置完成率、首次看到结果率、设置耗时、无金额模式选择率。
- 可信：结算修正率、公式展开率、工资条对账偏差中位数、预测到到账误差。
- 行为：日终结算完成率、D7/W4 有效结算留存、异常长班次率。
- 情绪：封账前后单题变化、文案“有帮助/打扰”率、情绪模块关闭率。
- 边界：准点下班率、完整休息率、封账后当日重开比例。
- 隐私：隐私模式启用率、无金额分享占比、删除成功率、工资字段外传事故数。
- 商业：试用到付费、买断/年付结构、退款率；不按工资水平分群定价。

**护栏指标：**工资字段外传事故 = 0；严重计算错误 = 0；使用后周加班时长不得显著上升；深夜非夜班推送率 = 0；负面/冒犯文案举报率设灰度停止阈值；误导性“法律应得”投诉一旦出现即复核相关页面。

### 10.3 实验计划

| 实验 | 变体 | 主指标 | 护栏 | 决策 |
|---|---|---|---|---|
| 价值主叙事 | 看钱涨 / 下班回血 / 工资算清 | 设置完成、次日回访 | 隐私退出、焦虑反馈 | 选首屏叙事，不改核心承诺 |
| 下班仪式 | 纯结算 / 结算+三步仪式 | 结算完成、封账后情绪变化 | 用时、跳过率、打扰率 | 若情绪无益且打扰高则简化 |
| 金额确定性 | 混合总额 / 三状态分栏 | 解释正确率、信任评分 | 首屏理解时间 | 必须确保不误把预计当到账 |
| 陪伴语气 | 极简 / 温柔 / 冷幽默 | 有帮助率、关闭率 | 冒犯举报 | 文案灰度，用户自主选择 |
| 隐私默认 | 伪装 / 直显 | 真实薪资录入完成率 | 后悔/切换、分享泄露 | 不以增长理由降低保护 |

实验不以“工作更久、赚得更多”作为正向结果。由于情绪自评存在选择偏差，需和访谈、卸载原因、提醒关闭率交叉验证。游戏化对幸福感的研究结果为积极与混合并存，不能把实验假设当成疗效。([系统综述](https://pubmed.ncbi.nlm.nih.gov/30135818/)，访问于 2026-10-13)

## 11. 商业化原则与价格假设

### 11.1 原则

1. **信任功能永久免费：**基础计算、基础班次、状态分栏、下班结算、隐私保护、删除和基础导出不得付费墙。
2. **不靠广告和数据变现：**不接基于薪资/情绪画像的广告，不出售聚合工资数据，不把“不上传”作为付费权益。
3. **为深化价值收费：**高级报表、年度回忆、复杂奖金/提成模型、多主题人格、Apple Watch、高级备份/私有同步。
4. **不按收入歧视定价：**不读取工资决定价格或优惠。
5. **不制造焦虑转化：**不以“数据即将丢失”“奖金算错了”恐吓购买。

### 11.2 价格假设

竞品集中在 ¥6/月、¥28–38/年、¥48–58 终身或低价一次买断，说明首发不宜高价强订阅。([竞品页面汇总](https://apps.apple.com/cn/app/doneat-%E4%B8%8B%E7%8F%AD%E5%80%92%E8%AE%A1%E6%97%B6/id6802803318)，访问于 2026-10-13)

建议测试：

- Free：今日闭环、基础奖金、隐私、30 天历史、CSV。
- Pro 买断：¥48–68，解锁高级报表、主题人格、无限历史、复杂规则模板。
- Pro 年度：¥28–38/年，包含持续更新的政策版本、跨设备私有同步与年度回忆；仅在持续服务确实存在时提供。
- 不在早期提供月订；如提供，须有明确持续价值且可随时取消。

最终价格需通过落地页意愿测试和付费访谈验证；商店价格只能作为定性信号，不能推断真实付费率。

## 12. 分阶段路线图与发布标准

### Phase 0：发现与冻结（2–3 周）

交付：12–15 人访谈；A/B/C 叙事原型；收入/状态词典；数据流图；30 个黄金计算案例；文案伦理清单；Web/iOS 技术方案。

退出条件：多数参与者能正确解释预计/应计/锁定/到账；80% 在 60 秒内完成封账原型；没有主流反馈认为产品鼓励加班；安全负责人签署数据流。

### MVP：今天闭环（4–6 周）

范围：月薪/时薪/无金额、固定排班、计薪/不计薪休息、基础加班、固定/比例/系数奖金、三状态结算、四种语气、下班仪式、本地加密、Face ID、后台/录屏遮罩、脱敏分享、CSV。

发布条件：P0 验收全通过；20+ 基础和 10+异常计算用例全绿；默认工资出站 0；敏感明文 0；严重崩溃 0；内部 dogfood 连续 7 天无数据丢失；法律/税务免责声明复核；App Store Privacy Manifest 与真实二进制一致。

### V1.1：工资周期闭环（再 4–8 周）

范围：周/月/年战绩、大小周/轮班/跨午夜、里程碑奖金、基础提成、夜班津贴、三情景预测、Live Activity/Widget、加密备份、工资周期对账。

发布条件：30 个复杂边界案例全绿；至少 2 周封闭测试；P95 异常班次率低于封测基线并有人工纠错路径；Widget/Live Activity 全表面真机隐私测试；预测偏差能解释而不覆盖历史。

### V1.5：个人劳动权益（8–16 周，需单独立项）

范围：阶梯提成、退款冲回、综合工时、地区化薪税、工资条本地 OCR、Apple Watch、可选私有同步、无金额祝福社交。

发布条件：薪税/劳动专业复核；新数据流威胁建模；云端删除与设备撤销可验证；OCR 原图默认不上传；任何社交面不可查看工资、工时排行或情绪详情。

### 当前代码迁移优先顺序

1. 将 Web `localStorage` 与 iOS `UserDefaults` 中的敏感数据迁移到目标架构。
2. 把单一 `SalaryData/SalaryProfile` 拆为 SalaryPlan、Schedule、Shift、CompensationRule、LedgerEntry、Settlement、MoodEntry、PrivacyPreference。
3. 建立纯函数计算内核、规则版本和跨端黄金测试向量，再扩 UI。
4. 重构首页为状态分栏和真实班次，不再用平均年秒数作为唯一真相源。
5. 实现结算协议与隐私发布闸门；最后才做角色皮肤和增长分享。

## 13. 风险、依赖与开放问题

| 风险/问题 | 影响 | 缓解与决策点 |
|---|---|---|
| 规则地区/公司差异巨大 | 错算导致失信或法律误导 | 用户口径优先；版本标签；专业复核；不宣称法定精确 |
| 固定月薪“今日价值”被理解为欠薪 | 核心概念误导 | 始终称劳动价值估算；工资周期固定薪资单列 |
| 情绪玩法幼稚或冒犯 | 用户流失、品牌伤害 | 默认极简；自嘲包主动开启；分人群可用性测试 |
| 实时数字诱导加班 | 与使命冲突 | 加班不奖励；护栏监测；必要时弱化秒跳 |
| Face ID/本地加密损害换机恢复 | 数据丢失 | 严格/标准本地两模式；加密导出；清晰说明取舍 |
| Web 无法提供原生同等级防护 | 隐私承诺被高估 | 默认会话；长期账本推荐 iPhone；诚实披露 XSS 边界 |
| iOS 后台刷新限制 | “不实时”投诉 | 以时间戳重算；Live Activity 展示结束时间而非依赖每秒推送 |
| 无遥测难以评估北极星 | 决策速度下降 | App Store 聚合 + 自愿匿名研究 + 本地指标截图访谈 |
| 买断难支持持续政策更新 | 商业不可持续 | 基础买断，高维护能力用透明年付；先验证付费意愿 |
| 云同步扩大合规面 | 破坏无出站承诺 | P1 独立立项、默认关闭、端到端恢复与删除先设计 |

**上线前必须回答：**

1. 首发只服务固定月薪/时薪，还是同时纳入日薪？
2. “已锁定”的最小凭据是用户手动确认，还是必须有工资条/回款？
3. 固定月薪首页默认展示劳动价值分摊还是仅展示下班进度？
4. 用户更愿意牺牲换机恢复换取严格本地，还是接受系统备份？
5. “老板来了”是否真有需求，还是普通遮罩足够？
6. 哪套角色/文案在不同职业、年龄和城市中不过度幼稚或冒犯？
7. Web 是否保留“记住此浏览器”，还是只做无持久化演示入口？
8. 首版发行地区、运营主体、年龄分级和隐私政策责任主体是谁？
9. 是否有能力持续维护法定节假日与薪税政策版本？若没有，不应上线自动政策规则。

## 结论

“下班回血器”的护城河不是更花哨的秒表，而是把**劳动事实、收入确定性、个人边界和隐私信任**放进同一个每日协议。只要一个数字无法解释、一次分享可能泄薪、一个奖励在暗示多加班，这个闭环就会失去成立条件；反过来，当用户能核对每一笔、明确哪些钱只是预计、完成一次真正的封账，情绪价值便不再依赖几句随机鸡汤。

因此，执行顺序应是：先冻结词典与公式，修复本地明文存储，建立跨端计算测试和结算状态机；再做 60 秒下班仪式；最后扩展主题、社交与政策能力。这个顺序把“准确和安全”当作情绪体验的地基，也让产品从容易被复制的实时工资页面，升级为值得长期托付的私人劳动价值账本。
